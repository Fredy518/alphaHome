# Features 刷新合同

SQL 普通表与 Python 特征表的全量、增量刷新共用目标表事务锁，取得锁后才开始计算。SQL 结果在数据库临时表中完成类型、业务键、日期范围及空结果校验，再在同一事务中对原表 DELETE/INSERT。提交失败或取消均回滚；原表 OID、依赖视图、索引、所有者、权限和触发器保留。全量刷新会产生 DELETE/INSERT 的 WAL 与死元组，需要在隔离演练后评估空间和维护窗口。

五个 SQL 普通表配方声明业务唯一键；正常刷新拒绝重复键。`unique_key_migration_sql(recipe)` 只生成存量唯一索引和非空约束 SQL，不连接数据库、不执行迁移。执行前必须归档存量、检查依赖和重复/空键，并记录原列约束用于回退。迁移 SQL 遇到同名索引会失败，不能凭名称跳过结构验证。禁止自动去重、删除依赖或重命名换表。

普通表只接受 full/incremental；物化视图只接受 full/concurrent。并发物化视图刷新默认拒绝能力缺失；显式 `allow_blocking_fallback=True` 仅允许在执行前确认缺少合格唯一索引或视图尚未填充时改用 full。权限、超时和执行错误均不触发回退。结果和刷新日志 details 分别记录 requested_strategy、effective_strategy、fallback_reason。刷新提交后的行数查询失败记为未知，不伪装为零行。

空结果默认失败并保留旧数据。允许清空的配方必须声明 `allow_expected_no_data`，并在同一连接上提供实际空集合判定理由。隔离数据库覆盖计算/类型/重复键/日期越界/空结果/取消/提交故障和并发重叠。20,000 行合成探针记录耗时、锁等待和 Python 分配峰值，仅验证此测试环境，不代表生产容量；数据库内存和大表 WAL 仍须在批准的演练环境测量。
