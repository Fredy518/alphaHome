# PIT 统一计划入口

`PITDataUpdateCoordinator.plan()` 是 GUI、命令行和兼容目标方法的共同预检。它在独立工作线程的只读 REPEATABLE READ 会话内读取合同、依赖闭包、结构、源观察值及实际日期规划结果；输出公共不可变 `RunPlan`。未知行数为 null；已有替换范围行数单独统计，不能混称本次计算行数。

执行提交原计划和 plan_hash，先验证请求及目标，再以原业务截止日重做只读预检；指纹变化或结构缺失均在业务写入前拒绝。全量月度计划保留配方原有的下一月影响传播规则；预检和执行调用同一日期规划方法，执行固定已提交的月份和日区间。依赖失败、部分成功或取消均阻止下游执行。GUI 的 PIT 批次整体交给协调器；Factors 的准备检查不会触发 PIT。

预检使用完整 PostgreSQL snapshot 字符串作为严格漂移检查的一部分，包含进行中的事务集合，不能用 xmin 一项替代。无关数据库写入也可能使计划失效，需要重新预检。计划限定执行范围与版本，不导出历史数据库快照；执行源读取仍应在结果中与已认证消费边界区分。PIT 尚无跨所有旧管理器的统一已消费源日志，审计会继续显示 consumption_unverified，不能据此宣称已全量消费。

正常 PIT 更新仅验证已安装结构，不自动建表、改列、创建索引或重装触发器。`python -m alphahome.pit.schema` 仅生成显式迁移 SQL；先归档原结构、权限、依赖及存量，再在批准范围内执行。事务中的唯一键冲突会使迁移失败，禁止自动删除重复历史。隔离验收已实际创建生成的 schema，并按全部已注册管理器验证字段和业务唯一键。

`python -m alphahome.pit.pit_data_update_production --target stock_fttm --mode incremental --dry-run` 不初始化任务工厂、不写运行日志或 schema。实际执行可附 `--expected-plan-hash` 和同一个 `--cutoff`。历史单管理器维护 CLI 不应作为新生产入口，统一入口清单见运维文档。

行业分类快照按月持锁后计算并校验，在同一事务内完成暂存、删除和插入；源失败、意外空集合、写入或提交失败保留原快照。部分批次提交的实际行数保留，失败计数不再被汇总过程覆盖。
