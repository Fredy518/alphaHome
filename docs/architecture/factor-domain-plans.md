# Factors 统一计划入口

FactorCoordinator 的真实数据库预检在单个只读 REPEATABLE READ 会话内生成不可变公共 RunPlan，涵盖请求、目标指纹、每项自然周五、P→G 日期传播、schema/约束/触发器、完整规划快照、源观察、公式合同、实现文件与配置指纹。兼容预检字段仍供界面显示，执行验证以 immutable_plan 与 plan_hash 为准。GUI 传递已预检计划，不再把 P/G 分成独立的通用任务执行。

`python -m alphahome.factors run ... --dry-run` 与 GUI 使用同一协调器。实际运行可传 `--expected-plan-hash` 和相同 `--as-of-date`。计划以 Asia/Shanghai 业务日冻结“严格早于本日的最近自然周五”。执行取得计算锁后，按原业务日重做只读预检；源或结构漂移在创建运行日志和业务写入前拒绝。完整快照检查可能因无关数据库写入而保守失效，不应降低为单独 xmin 检查。

整批计算的锁顺序为共享修复会话锁、排他计算会话锁、单日期事务锁。计算会话锁在打开源快照之前获取，跨 P→G 和各日期提交持有；修复/回滚使用排他修复锁。同步工作线程被异步取消时，先发出停止信号并等待它关闭，再传播取消；已提交结果保留在日志和取消回调中。

P 的源合同现在包含 tushare.stock_basic。消费边界用 ts_code、list_status、list_date、delist_date 的稳定内容指纹，避免 stock_basic 日常全量维护仅更新 update_time 就触发所有历史日期。资格字段或成员集合改变会使声明的历史窗口重验，并继续受自动日期数量上限约束。规划之后资格指纹改变，整项消费水位不晋升。旧日志没有这一源的证明，不能作为新合同的可信基线。

P v2.0、G v1.1 公式、自然周五和同日 P→G 保持原合同。普通 PIT 财务源的插入/修订继续使用时间戳加 MVCC 游标；硬删除、TRUNCATE 和源维护仍按既有 ADR 使基线失效并重验，不能当成一般 CDC。迁移和历史重验只准备方案，本次代码交付不执行生产回填。
