# ADR 002：来源快照、消费水位与时点

状态：采纳。计划观察、实际读取快照和批末观察是三个独立事实。Factors 每个任务在独立 `REPEATABLE READ READ ONLY` 事务内计算，G 在 P 提交后获取自己的快照。任意指定历史 `source_cutoff` 不具备快照重建能力，明确拒绝。

`snapshot_consumed_v2` 同时保存来源更新时间和快照 xmin。仅成功完成全部计划日期、拥有相应当前提交账本、并覆盖声明的维护窗口，才能推进消费边界；取计划与实际快照两者的保守值。完整历史运行覆盖实际来源历史；默认 smart 认证最近 730 天窗口，局部覆盖不认证全局基线。批末观察不能推进消费水位。

更新时间不能单独捕获在旧事务中产生、后来才提交的变更。增量查询增加元组 xmin 与已消费快照 xmin 的比较；长事务会导致保守的重复处理。事务号游标保留 64 位值，跨度达到 2^31 时拒绝继续增量并要求重新核验。脏来源扫描设置 30 秒查询上限，超时不会转成“无变化”。xmin 和快照的含义依据 [PostgreSQL 17 官方文档](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-PG-SNAPSHOT)。

该检测协议覆盖插入与更新，并不是通用 CDC。对源表执行硬删除、TRUNCATE、重写历史时，维护操作必须使消费基线失效并进行完整范围核验，或另行采用包含删除事件的变更日志；禁止仅凭旧时间水位宣布来源未变。当前代码重构不执行这些生产维护操作。

源表中的业务 PIT 时间、计算日期、快照观察时间、实际执行时间、审计时间分别记录。修订后数据上的历史重算应标注为事后重算，不能冒充当时可见的原始快照。
