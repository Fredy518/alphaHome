# FTTM 一级、二级行业 PIT 实施与验收记录

> 实施日期：2026-08-25（Asia/Shanghai）
> 实施状态：Validate 通过（数据合同、代码、2014 年以来全历史回填与审计快照）
> 边界：不构成行业 FTTM 因子有效性、样本外有效性或生产投资授权

## 实施版本

- 个股公式：`fttm_q4_report_event_linear_v1`
- 行业聚合：`org_mv_weighted_then_equal_mean_v1`
- 质量规则：`coverage_gate_v1`
- 权重口径：`total_mv`（研究代理，不是申万官方指数权重）

## 实现确认

- FY1/FY2 只在同一 `(ts_code, org_name, author_name, report_date)` 事件内配对。
- `np` 优先；仅允许 `report_date == trade_date` 的 `eps × total_share` 回退。
- 六个月窗口为左开右闭；先计算事件 FTTM，再选股票—机构月末最新事件。
- 一级、二级行业均使用同月申万动态成分和 PIT-time 上市/退市状态。
- 行业内先按机构实际覆盖股票重新归一化 `total_mv`，再对机构值做算术平均。
- 环比与扩散度只连接立即前一个自然月；无匹配机构时扩散度为空。
- 当最早写入月缺少已持久化的前月个股锚点时，从原始研报只读补算该锚点并仅用于本批计算，不把锚点越界写入目标表。
- 低覆盖行业保留结构行，并以稳定 JSON 原因数组标记质量。
- 重算月通过 staging 校验后在同一事务中删除并重写，避免源行删除后遗留旧数据。

## HANDOFF DDL 差异

`org_mv_weighted_then_equal_mean_v1` 长 34 个字符，而 HANDOFF 建议的 `aggregation_version varchar(32)` 无法保存该固定版本名。正式 DDL 将该列扩为 `varchar(64)`；版本值和聚合语义没有改变。首次发现时行业写入事务完整回滚，修正列宽后重跑成功。

## GUI 全历史加载性能

全历史回填后，PIT 管理页原实现会对每个任务串行聚合全部历史期间的覆盖数。当前 8 个 PIT 任务的真实加载耗时为 19.8393 秒，其中实时表统计占 19.7964 秒；特征列表自身仅需 0.0674 秒，但启动时被串行排在 PIT 之后。

2026-08-25 完成以下修复：

- 覆盖率从“全历史一次性分组”改为“从最新候选期向前逐期检查”，保留最新有效期与低覆盖回退语义。
- 8 个 PIT 任务的实时统计并发执行；当前上市股票分母通过异步锁只加载一次。
- GUI 启动时并发请求数据采集、PIT、特征和设置，特征列表不再等待 PIT。
- 控制器复用桌面入口已建立的数据库连接池，不再启动后立即关闭并重建。
- 精确总行数查询耗时较小且属于可信展示字段，因此继续保留，没有改成近似统计。

修复后同一 AlphaDB 上 PIT 列表加载为 0.7248 秒，较修复前减少约 96.3%；特征列表为 0.0649 秒。8 个任务的新旧覆盖期和覆盖数逐项一致，差异 0。

## 已知限制

- 源表没有在本任务中采用经过验证的行级变更日志；日常增量保证最近 8 个完整月及相邻月传播，但不能声称自动捕获任意久远的历史补录或删除。
- 2010–2013 年虽有部分源数据，但不在 HANDOFF V1 默认历史范围内；若要扩展到 2014 年以前，仍应先输出年度覆盖率剖面，再显式变更数据合同并重跑验收。
- 月末快照只声明收盘后可生成，最早在 `obs_date` 后首个交易日使用；日级 `report_date` 不支持盘中可见性声明。
